## 后续修改流程

1. 获取私有生产分支的最新提交，先检查是否存在尚未合并的修改。
2. 在最新源码上实现需求，运行相关功能测试、类型检查和构建；数据库改动追加迁移，保留既有生产绑定、运行时秘密与数据。
3. 将验证后的修改提交至生产分支，触发既有 Cloudflare 自动构建与部署。
4. 检查 Cloudflare 构建结果和正式网站受影响的功能。仅提交代码不足以证明上线成功；无法获得部署状态时明确记录验证限制。
5. 将同一业务改动同步到本公开仓库；继续使用公开部署示例配置，不提交生产秘密、真实答卷、名册、数据库文件或备份。

日常界面、问卷、班务与后台功能可沿此链路完成。新增外部服务、运行时密钥或账号权限时，需另行配置相应资源。Cloudflare 授权失效、额度或账单异常也可能需要账号持有人处理。

## Cloudflare 构建配置

现有连接记录的构建命令为 `pnpm run build`，部署命令为 `pnpm run deploy`；后者先应用 D1 迁移，成功后发布 Worker。构建令牌需要对应账号的 D1 编辑权限。域名路由、管理员密码和答卷不随公开代码复制。
